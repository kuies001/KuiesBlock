# KuiesBlock v0.6.0

**主題：與系統 Wi-Fi、無線偵錯與私人 DNS 共存**

## 這次修了什麼

- **無線偵錯顯示正確的 Wi-Fi 位址。** 系統的無線偵錯頁面會讀取「Settings 程序自己的
  預設網路」；過去 VPN 涵蓋系統 UID，頁面因此顯示 `10.111.222.1`。現在建立隧道時
  固定讓系統 UID（1000）留在實體網路上，頁面恢復顯示 Wi-Fi 的實際位址。
- **私人 DNS 不再被 KuiesBlock 單方面拖垮。** 私人 DNS 設定頁與狀態同樣以系統 UID 的
  預設網路為準；先前它會描述一個無法完成 strict DoT 的 VPN 網路。現在系統元件維持
  實體網路視圖，私人 DNS 的驗證由該網路正常完成。

## 沒有改變的事

- 仍是 **DNS-only VPN**，沒有改成全流量隧道，也沒有引入任何第三方 VPN 核心。
- strict 私人 DNS 下仍採「不宣告 DNS」的共存方式；本機規則不參與該模式的解析，
  介面會如實標示。
- 本機過濾清單、寬鬆／標準／嚴格／自訂模式、切換後自動更新、8／24 小時週期、
  DNS 自動備援與 Cloudflare DoH、主要 DNS 自動恢復、fail-open、App 個別排除、
  背景執行保護、App 內更新、主題、開機自動恢復與既有設定全部保留。

## 已知限制（如實標示）

- **strict 私人 DNS**：系統的加密 DNS 會繞過本機規則，查詢計數維持「無資料」。
- **私人 DNS 設定頁的「無法連線」字串**：在測試機上無法重現，該字串本身列為
  INCONCLUSIVE；可重現的系統層失敗表徵（VPN 網路 `PrivateDnsBroken` 與
  「這個網路沒有網際網路連線」通知）在修正後不再出現。
- **DNS 自動備援切回主要 DNS**：換手與備援期間的本機攔截已實機驗證；解除故障後
  自動切回的那一行記錄未能在 adb 斷線前讀取，列為 INCONCLUSIVE。

## 實機驗證摘要

- 無線偵錯頁面顯示 Wi-Fi 位址與連接埠，`adb connect` 以該位址成功。
- Wi-Fi 斷線再重連：同一條隧道（netId 不變）不需重啟，App 內解析正常。
- 正常模式攔截：對虛擬 DNS 的探測回 `NXDOMAIN` 且本機封鎖計數增加。
- 備援注入：主要 DoH 失敗後備援接手、不重建隧道，備援期間本機規則仍生效。
- 單元測試與 debug 建置通過。
